DynImg

Compose GUI primitives into a CPU-rasterized canvas, then apply that canvas as a 3D part's Texture. Mutating the underlying primitives updates the texture every frame, so a Lua-driven UI becomes a live decal you can wallpaper onto a part. 

local DynImg     = import("DynImg")
local GUI        = import("GUI")
local Asset      = import("Asset")
local Renderable = import("Renderable")
local Vector     = import("Primitives").Vector
local Color3     = import("Primitives").Color3

How it works

  1. Build GUI primitives the same way you'd build on-screen UI (GUI.Basic.Image, GUI.Basic.Square, GUI.Basic.Font, …).
  2. Hand them to DynImg.New(width, height, { … }). Each primitive has its .Visible flipped to false and is tagged as canvas-owned so it no longer draws on the regular GUI overlay.
  3. Assign the resulting DynImg as a part's .Texture: part.Texture = canvas. The 3D part displays the live canvas, refreshed every frame.

The canvas is a fixed-size width × height RGBA8 pixel buffer. Each frame the engine re-rasterizes the canvas: sorts the primitives by ZIndex ascending, then alpha- blends them onto the buffer. Primitives' .Position and .Size are read in pixel-space, with (0, 0) at the top-left of the canvas (NOT the screen).

DynImg API

DynImg.New(width, height, primitives?) → DynImg

Build a fresh canvas of the given pixel size. The primitives list is optional, you can also :Add later. Order in the list doesn't matter, draw order is determined by each primitive's ZIndex at composition time.

DynImg properties

.Widthnumberread-only
.Heightnumberread-only
.IsAlivebooleanread-only

DynImg methods

canvas:Add(primitive)

Add an existing GUI primitive to the canvas. Sets primitive.Visible = false and routes the primitive into this DynImg only. A primitive can only belong to one DynImg at a time, adding it to a second silently re-tags ownership.

canvas:Remove(primitive)→ boolean

Remove a primitive from the canvas. Returns true if it was in the list. Clears the canvas-ownership tag, but leaves primitive.Visible at false — set it back to true yourself if you want the primitive to appear on the regular GUI again.

canvas:Destroy()

Tear down the canvas. Owned primitives stay alive (the canvas doesn't destroy them) but are released from this DynImg. The texture buffer is freed on the next renderer-side eviction sweep.

Example: floating speech bubble

-- A 256×128 canvas: a translucent square background plus a text label.
local bg = GUI.Basic.Square()
bg.Size         = Dim.new(256, 128)
bg.Position     = Dim.new(0, 0)
bg.Color        = Color3.new(0, 0, 0)
bg.Transparency = 0.4
bg.ZIndex       = 0

local font = Asset.GetAsset("Font", "ui.label")
local txt  = GUI.Basic.Font(font)
txt.Position  = Dim.new(12, 40)
txt.Text      = "hello!"
txt.TextSize  = 48
txt.TextColor = Color3.new(1, 1, 1)
txt.ZIndex    = 1   -- drawn on top of bg

local canvas = DynImg.New(256, 128, { bg, txt })

-- Apply it to a 3D part standing in the world.
local part = Renderable.BasePart("Cube")
part.Size    = Vector.new(2, 1, 0.05)
part.Texture = canvas

-- Mutate the text — the texture refreshes on the next frame.
txt.Text = "new line!"

Limitations of v1

  • Shape support: Image, Square, and baked Text primitives composite as colored / tinted rectangles. Circle and Triangle are drawn as their bounding rectangle. Sub-pixel anti-aliasing on the non-rectangle shapes is not yet implemented.
  • 2D shaders not applied: per-primitive fragment shader attachments (primitive:AttachShader) are skipped during canvas composition. Use a 3D fragment shader on the consuming BasePart instead, see Renderable shader docs.
  • One canvas per primitive: a primitive can only belong to one DynImg at a time. If you need the same content in two canvases, build two primitives.
  • CPU cost: composition runs on the CPU every frame, so very large canvases or hundreds of layered primitives will start to show in your frame time. Aim for canvases at the resolution you actually need on the part — a 512×512 panel is fine, a 4096×4096 panel is not.
