DynMesh

Runtime "skeleton" wrapped around a base BasePart. Weld extra parts to fixed local-space points, to specific vertices on the source mesh (vertex follows live deformation / animation), or stretch a part between multiple anchors. Built for character attachments (swords, helmets, capes) and for skin-style customization where pieces snap onto a shared base mesh. 

local DynMesh = import("DynMesh")
local Renderable = import("Renderable")
local Asset = import("Asset")
local Vector = import("Primitives").Vector

local body = Renderable.BaseModel(Asset.GetAsset("Model", "chars.hero_body"))
local dm = DynMesh.new(body)

-- Hat: rigid attach. Sits on the head, no animation of its own.
local hat = Renderable.BaseModel(Asset.GetAsset("Model", "gear.tophat"))
dm:Weld(hat, {
    kind = "Attach",
    point = Vector.new(0, 1.7, 0),
    name = "hat",
})

-- Upper body: hierarchical Joint, plays its own breathing animation
-- on top of whatever the lower body is doing.
local upper = Renderable.BaseModel(Asset.GetAsset("Model", "chars.hero_torso"))
dm:Weld(upper, {
    kind = "Joint",
    point = Vector.new(0, 1.0, 0),
    name = "torso",
})
upper:GetTrack("breathing"):Play()  -- runs in torso's local frame

-- Cape stretched between two vertices on the body mesh.
local cape = Renderable.BasePart("Cube")
dm:Stretch(cape, { { vertex = 88 }, { vertex = 312 } })

-- Look up by name later.
local got = dm:GetPartByName("torso")

DynMesh API

DynMesh.new(base) -> DynMesh

Wrap a BasePart as a DynMesh. Welds added to the returned handle update once per heart tick relative to the base part's pose.

DynMesh

dm:Weld(target, opts?) -> number (weld id) method

Weld a BasePart to this mesh. Returns the weld id for :GetPart / :Detach. Options:

  • kind = "Static" | "Attach" | "Joint", default "Static":
    • Static / Attach — rigid follow. On link the target's current world CFrame is captured as the local offset, so the part visually stays put instead of snapping to the base. Each tick the part tracks the base. If you reassign target.CFrame between ticks, the new pose is captured as the new local offset, ideal for eyes that look around or limbs that pose locally while the body moves. Animations playing on the welded part are still overwritten by the weld.
    • Joint — hierarchical follow. The welded part is dragged along by the base's per-tick motion but keeps its own pose on top, so animation tracks playing on the welded part keep working as a "local pose" relative to the welded position. Use this when a child part has its own FBX animation (upper / lower body, jointed limbs, etc.).
  • point = Vector, fixed offset in the base part's local space. Setting point or rotation overrides the capture-on-link behaviour above — the offset comes from the options, not the target's current world pose.
  • rotation = Vector, additional Euler rotation offset.
  • vertex = number, a vertex index on the base mesh; the welded part follows that vertex live (deform / animation aware). Mutually exclusive with point / rotation.
  • name = string, optional label for :GetPartByName / :DetachByName.
Calling without opts welds the target where it currently stands — capture-on-link.

dm:Stretch(target, anchors) -> number method

Stretch target along a polyline of anchor points. Each anchor is { point = Vector } (a fixed offset in the base part's local space) or { vertex = number } (a vertex index on the base mesh — live-tracked, deform- and animation-aware). Per tick the engine:

  • Resolves every anchor to a world-space point.
  • Sets target.CFrame.Position to the centroid (average) of all anchors.
  • Sets target.CFrame.Rotation to face the first -> last anchor (yaw + pitch).
  • Sets target.Size.x to the total polyline length (sum of consecutive anchor-to-anchor distances), so non-collinear waypoints stretch the part further than the straight span.
The part itself stays straight — see examples below for how to chain multiple stretches into a bent rope / arc. :Detach restores the target's original X size.

dm:Detach(weld_id) -> boolean method

Remove a weld by id. The welded BasePart is not destroyed — it stays alive in the scene at its last computed pose and just stops being driven by this DynMesh. Stretch welds restore the target's original X Size on detach; Joint welds release their parent-follow state. Animation tracks running on the welded part keep playing and now own the cframe uncontested.

dm:DetachByName(name) -> boolean method

Same as Detach but matches by the optional name passed at weld time. Removes every weld with that name in one call.

dm:DetachPart(target) -> boolean method

Same as Detach but matches by the BasePart userdata directly, useful when you have the part in hand but don't remember its weld id.

dm:Clear() -> number method

Detach every weld at once. Returns the number removed. Useful for skin / customization preset swaps, drop the current welds and re-Weld the new pieces rather than rebuilding the whole rig.

dm:GetPart(weld_id) -> BasePart? method

Return the BasePart welded under weld_id, or nil if no such weld exists. Same userdata you originally passed to :Weld / :Stretch.

dm:GetPartByName(name) -> BasePart? method

Look up a welded part by the name you passed at weld time. Useful for character rigs where you want to grab "left_arm" or "helmet" without remembering the numeric id.

dm:GetParts() -> {{ Id, Name?, Part }} method
dm:GetBase() -> BasePart method
dm:IsAlive() -> boolean method

True if both the DynMesh and its base part are still alive. Goes false automatically when the base BasePart is destroyed (e.g. via Asset.Drop on the base mesh's ModelAsset). Useful for tearing down rig state when content is unloaded under you.

dm:Destroy() method

Stop running the per-tick weld update. Welded parts stay alive and where they were last placed, they just stop following the base part. Asset.Drop on the base mesh's ModelAsset implicitly does this (and pruning kicks in on the next tick).

Drop awareness. Asset.Drop destroys the BaseParts using a content asset (Image / Model / Font / Sound). DynMesh notices on the next tick: dead welds are pruned automatically, and a DynMesh whose base BasePart died is marked dead and stops ticking. You don't need to manually clean up welds when their underlying asset is dropped.
Vertex anchors are live. A vertex anchor reads the live world position of that vertex each tick, so it tracks deformation, animation, and explicit part.CFrame moves. Make sure the index is in range, out-of-range indices fall back to the base part's origin.

Locally-posed welds — eyes, limbs, look-around

Static / Attach welds are capture-on-link: when you call :Weld without an explicit point / rotation, the welded part's current world CFrame is snapshotted as the local offset relative to the base. This gives you two useful properties:

  • The part doesn't visually snap when you weld it — it stays exactly where you placed it before linking.
  • If you later reassign target.CFrame, the new pose becomes the new local offset. The part keeps tracking the base, but with the freshly-set rotation / translation applied locally.

The canonical use is eyes welded to a head. Each tick the eyes follow the head's position; in between, you set eye.CFrame to point them somewhere, and they keep looking that way as the head moves around. Same idea for limbs posed locally on a body that's flying through the world. 

local dm  = DynMesh.new(head)
local id  = dm:Weld(eye_l)              -- captures eye_l's current world CFrame

-- Look 20° to the right (locally — head still moves the eye around).
eye_l.CFrame = CFrame.new(eye_l.CFrame.Position, Vector.new(0, math.rad(20), 0))

On :Detach the welded part stays at whatever world CFrame the weld last set, so the eye doesn't snap back to its pre-weld pose — another consequence of the capture-on-link semantics.

To get the old "snap to a fixed local offset" behaviour, pass point and / or rotation in the opts table. Those override the capture and the welded part is repositioned to base + point on the first tick: 

local hat_id = dm:Weld(hat, { point = Vector.new(0, 1.1, 0) })

Stretch examples

A few patterns that come up in practice. Every example assumes you've already created a DynMesh wrapping a base part: 

local DynMesh = import("DynMesh")
local Renderable = import("Renderable")
local Vector = import("Primitives").Vector

local body = Renderable.BaseModel(Asset.GetAsset("Model", "chars.hero"))
local dm = DynMesh.new(body)

Two-point stretch (sleeve, strap, simple tendon)

The basic case: pin a thin part between two anchors. A cube with Size (1, 0.05, 0.05) shows up as a 5cm-thin strap spanning from anchor to anchor. The cube's X-axis becomes the span direction, so its Y and Z faces are perpendicular to it. 

local sleeve = Renderable.BasePart("Cube")
sleeve.Size = Vector.new(1, 0.05, 0.05)
sleeve.Color = Color3.FromRGB(200, 100, 50)

-- Connect shoulder vertex to wrist vertex on the body mesh.
-- As the body's arm animation deforms those vertices, the sleeve
-- follows in real time.
dm:Stretch(sleeve, {
    { vertex = 88  },  -- shoulder
    { vertex = 312 },  -- wrist
})

Three-point stretch (around a corner / pulley)

Add a mid-anchor that's off the straight line between start and end. The total polyline length grows past the straight-line distance, so the part stretches longer to match. Useful for a rope-like piece that drapes over a hook or a strap that wraps a shoulder before crossing the chest. 

local strap = Renderable.BasePart("Cube")
strap.Size = Vector.new(1, 0.04, 0.04)

dm:Stretch(strap, {
    { vertex = 88  },                                -- left shoulder
    { point  = Vector.new(0, 1.2, 0.18) },        -- waypoint over the chest
    { vertex = 412 },                                -- right hip
})

-- The strap's X-size = (88 -> chest) + (chest -> 412), so it's longer
-- than the straight 88 -> 412 distance. The strap is centered on the
-- centroid of all three anchors and oriented from anchor[0] toward
-- anchor[last].

Repositioned stretch (anchors that move every frame)

Vertex anchors track the live mesh. As the parent runs an animation track, the welded vertices move and the stretch reshapes itself automatically — no per-frame Lua code: 

local arc = Renderable.BasePart("Cube")
arc.Size = Vector.new(1, 0.08, 0.08)
arc.Color = Color3.FromRGB(120, 220, 255)

-- Hand-to-hand electric arc that follows the live wrist vertices.
dm:Stretch(arc, {
    { vertex = 312 },  -- left wrist
    { vertex = 488 },  -- right wrist
})

body:GetTrack("cast_spell"):Play()
-- The arc reshapes per tick to match where the wrists are right now,
-- including any deformations the animation applies.

Explicit reposition (changing anchors at runtime)

Sometimes the path itself needs to change — a rope re-pinning onto a different vertex when the player picks up a new tool, a cable swinging to a new attachment point. Just detach the old stretch and re-stretch with new anchors: 

local cable = Renderable.BasePart("Cube")
cable.Size = Vector.new(1, 0.06, 0.06)

local id = dm:Stretch(cable, {
    { vertex = 88 },
    { vertex = 312 },
})

-- Later, swap the path. The cable BasePart is reused, no flicker.
dm:Detach(id)
id = dm:Stretch(cable, {
    { vertex = 88 },
    { point  = Vector.new(0.3, 1.5, 0) },
    { point  = Vector.new(-0.3, 1.5, 0) },
    { vertex = 488 },
})

Multi-segment stretch (genuinely bent rope)

A single Stretch always renders as a straight part — the part itself doesn't bend. For a rope that actually curves, chain multiple stretches with shared interior waypoints. Each segment is its own BasePart welded with its own Stretch call, and consecutive segments share anchors so the joints stay seamless: 

local waypoints = {
    Vector.new(0,    2.0,  0),
    Vector.new(0.4,  1.7,  0.1),
    Vector.new(0.7,  1.2,  0.3),
    Vector.new(0.5,  0.7,  0.5),
    Vector.new(0,    0.4,  0.5),
}

-- One straight cube per segment.
for i = 1, #waypoints - 1 do
    local seg = Renderable.BasePart("Cube")
    seg.Size = Vector.new(1, 0.05, 0.05)
    dm:Stretch(seg, {
        { point = waypoints[i]     },
        { point = waypoints[i + 1] },
    })
end
-- 4 segments laid end-to-end. Each is straight, but the assembly
-- traces the full polyline of waypoints. Mix in vertex anchors for
-- sections that should follow the live mesh.

Mixing point and vertex anchors

Anchors can be any combination of fixed local-space points and live mesh vertices. This is the typical pattern for cosmetics that pin to character geometry but route through cosmetic waypoints (a sash that exits at a vertex, drapes through an accessory clip, then anchors back at another vertex): 

dm:Stretch(sash, {
    { vertex = 88                     },  -- left shoulder vertex
    { point  = Vector.new(-0.4, 1.4, 0.2) },  -- clip A (fixed)
    { point  = Vector.new(-0.2, 0.9, 0.4) },  -- clip B (fixed)
    { vertex = 412                    },  -- right hip vertex
})
How total length works. The X-size is computed as the sum of consecutive anchor-to-anchor distances. Adding a midpoint that's collinear with the start and end is a no-op (the sum equals the straight span). Adding an off-axis waypoint adds the detour length. Removing or moving anchors at runtime (via Detach + re-Stretch) resizes the part accordingly.

Combining welds and stretches

A common pattern: weld an accessory to a fixed spot on the rig, then drive deformations / warping on it via stretches. A hat sits on the head, and a ribbon trailing off the hat warps with stretch anchors. A pauldron is welded to the shoulder, and shoulder-tassels stretch off the pauldron. A sword is welded to the hand, and a glow-aura stretches between the blade tip and the hand vertex.

The rule that makes this work: welds and stretches can't share the same target part (the second one overwrites the first every tick — last weld wins on a given target). To combine them, build a small hierarchy: weld the primary part to its anchor, then wrap that primary part as its own DynMesh and use it as the anchor for stretches. The whole chain follows the original parent automatically.

Hat with a warping ribbon trailing off the back

local DynMesh    = import("DynMesh")
local Renderable = import("Renderable")
local Asset      = import("Asset")
local Vector     = import("Primitives").Vector

-- 1. Weld the hat to the head's local-space spot. This part is
--    rigid: it just sits +1.7Y above the head and follows it.
local head = Renderable.BaseModel(Asset.GetAsset("Model", "chars.head"))
local head_dm = DynMesh.new(head)

local hat = Renderable.BaseModel(Asset.GetAsset("Model", "gear.tophat"))
head_dm:Weld(hat, {
    kind  = "Attach",
    point = Vector.new(0, 1.7, 0),
    name  = "hat",
})

-- 2. Wrap the hat itself as a DynMesh. Now we can attach things
--    in the HAT'S local space, and they'll inherit the head's
--    motion automatically (because the hat is welded to the head).
local hat_dm = DynMesh.new(hat)

-- 3. Stretch a ribbon off the hat with multiple waypoints, so
--    bobbing/warping comes through the stretch system. The waypoints
--    are in the hat's local space, so they ride the head + hat
--    transforms transparently.
local ribbon = Renderable.BasePart("Cube")
ribbon.Size = Vector.new(1, 0.05, 0.05)
ribbon.Color = Color3.FromRGB(200, 40, 40)

local ribbon_id = hat_dm:Stretch(ribbon, {
    { point = Vector.new(0,     0.2,  -0.05) },  -- pinned to the hat brim
    { point = Vector.new(0.05, -0.1, -0.3)  },  -- mid-bend
    { point = Vector.new(0,     -0.4, -0.5)  },  -- tail tip
})

What happens at runtime:

  1. The head moves / rotates / animates.
  2. head_dm tick fires the hat's static weld, hat sits +1.7Y above the head's current world position.
  3. hat_dm tick fires the ribbon's stretch, ribbon is computed in the hat's current world frame (the one the head_dm just set).

Net effect: ribbon waypoints look stable to the hat, and the hat looks stable to the head. Move any anchor (say, animate the second ribbon waypoint via Detach + re-Stretch each frame) and you get warping deformation that still respects the rig hierarchy.

When you don't need the combo

If you just want a part to bend / stretch between two live mesh points, a single :Stretch with vertex anchors is enough — no weld required. A sleeve between shoulder and wrist is one Stretch call. The combo pattern is only needed when:

  • The accessory has a fixed offset from the rig (so a Weld with a point is the right tool for that part of the chain), AND
  • You want further parts to stretch / warp relative to that accessory (so a child DynMesh wrapping the welded part is the right tool for those).

Animating the warp anchors

Stretches automatically follow live vertex anchors, but you can also animate point anchors over time by re-stretching each frame with new offsets. This gives you procedural warping on top of the welded base: 

local Process = import("Process")

local t = 0
Process.Heartbeat:Connect(function(dt)
    t += dt
    local wave = math.sin(t * 3) * 0.1

    hat_dm:Detach(ribbon_id)
    ribbon_id = hat_dm:Stretch(ribbon, {
        { point = Vector.new(0,           0.2,  -0.05) },
        { point = Vector.new(0.05 + wave, -0.1, -0.3)  },
        { point = Vector.new(wave * 0.5,   -0.4, -0.5)  },
    })
end)

The hat's static weld keeps it pinned to the head. The ribbon's stretch reshapes per frame to follow the wave. The two systems don't conflict because they're on different DynMesh layers.
