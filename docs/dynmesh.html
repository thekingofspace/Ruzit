DynMesh

Runtime "skeleton" wrapped around a base BasePart. Weld extra parts to fixed local-space points, to specific vertices on the source mesh (vertex follows live deformation / animation), or stretch a part between multiple anchors. Built for character attachments (swords, helmets, capes) and for skin-style customization where pieces snap onto a shared base mesh. 

local DynMesh = import("DynMesh")
local Renderable = import("Renderable")
local Asset = import("Asset")
local Vector = import("Primitives").Vector

local body = Renderable.BaseModel(Asset.GetAsset("Model", "chars.hero_body"))
local dm = DynMesh.new(body)

-- Hat: rigid attach. Sits on the head, no animation of its own.
local hat = Renderable.BaseModel(Asset.GetAsset("Model", "gear.tophat"))
dm:Weld(hat, {
    kind = "Attach",
    point = Vector.new(0, 1.7, 0),
    name = "hat",
})

-- Upper body: hierarchical Joint, plays its own breathing animation
-- on top of whatever the lower body is doing.
local upper = Renderable.BaseModel(Asset.GetAsset("Model", "chars.hero_torso"))
dm:Weld(upper, {
    kind = "Joint",
    point = Vector.new(0, 1.0, 0),
    name = "torso",
})
upper:GetTrack("breathing"):Play()  -- runs in torso's local frame

-- Cape stretched between two vertices on the body mesh.
local cape = Renderable.BasePart("Cube")
dm:Stretch(cape, { { vertex = 88 }, { vertex = 312 } })

-- Look up by name later.
local got = dm:GetPartByName("torso")

DynMesh API

DynMesh.new(base) → DynMesh

Wrap a BasePart as a DynMesh. Welds added to the returned handle update once per heart tick relative to the base part's pose.

DynMesh

dm:Weld(target, opts?) → number (weld id) method

Weld a BasePart to this mesh. Returns the weld id for :GetPart / :Detach. Options:

  • kind = "Static" | "Attach" | "Joint", default "Static":
    • Static / Attach — rigid follow. The welded part's CFrame is fully driven by the base each tick. Animations on the welded part are overwritten. Use for hats, stickers, props pinned to a fixed local-space point.
    • Joint — hierarchical follow. The welded part is dragged along by the base's per-tick motion but keeps its own pose on top, so animation tracks playing on the welded part keep working as a "local pose" relative to the welded position. Use this when a child part has its own FBX animation (upper / lower body, jointed limbs, etc.).
  • point = Vector, fixed offset in base part's local space.
  • rotation = Vector, additional Euler rotation offset (only applied on the snap tick for Joint).
  • vertex = number, a vertex index on the base mesh; the welded part follows that vertex live (deform / animation aware). Mutually exclusive with point / rotation.
  • name = string, optional label for :GetPartByName / :DetachByName.
Calling without opts welds rigidly at the base part's origin.

dm:Stretch(target, anchors) → number method

Stretch target between two or more anchor points. Each anchor is { point = Vector } or { vertex = number }. The target part is repositioned at the midpoint of the first and last anchor and its X-axis Size is set to the distance between them, so a thin cube becomes a tendon-like span.

dm:Detach(weld_id) → boolean method

Remove a weld by id. The welded BasePart is not destroyed — it stays alive in the scene at its last computed pose and just stops being driven by this DynMesh. Stretch welds restore the target's original X Size on detach; Joint welds release their parent-follow state. Animation tracks running on the welded part keep playing and now own the cframe uncontested.

dm:DetachByName(name) → boolean method

Same as Detach but matches by the optional name passed at weld time. Removes every weld with that name in one call.

dm:DetachPart(target) → boolean method

Same as Detach but matches by the BasePart userdata directly, useful when you have the part in hand but don't remember its weld id.

dm:Clear() → number method

Detach every weld at once. Returns the number removed. Useful for skin / customization preset swaps, drop the current welds and re-Weld the new pieces rather than rebuilding the whole rig.

dm:GetPart(weld_id) → BasePart? method

Return the BasePart welded under weld_id, or nil if no such weld exists. Same userdata you originally passed to :Weld / :Stretch.

dm:GetPartByName(name) → BasePart? method

Look up a welded part by the name you passed at weld time. Useful for character rigs where you want to grab "left_arm" or "helmet" without remembering the numeric id.

dm:GetParts() → {{ Id, Name?, Part }} method
dm:GetBase() → BasePart method
dm:IsAlive() → boolean method

True if both the DynMesh and its base part are still alive. Goes false automatically when the base BasePart is destroyed (e.g. via Asset.Drop on the base mesh's ModelAsset). Useful for tearing down rig state when content is unloaded under you.

dm:Destroy() method

Stop running the per-tick weld update. Welded parts stay alive and where they were last placed, they just stop following the base part. Asset.Drop on the base mesh's ModelAsset implicitly does this (and pruning kicks in on the next tick).

Drop awareness. Asset.Drop destroys the BaseParts using a content asset (Image / Model / Font / Sound). DynMesh notices on the next tick: dead welds are pruned automatically, and a DynMesh whose base BasePart died is marked dead and stops ticking. You don't need to manually clean up welds when their underlying asset is dropped.
Vertex anchors are live. A vertex anchor reads the live world position of that vertex each tick, so it tracks deformation, animation, and explicit part.CFrame moves. Make sure the index is in range, out-of-range indices fall back to the base part's origin.
