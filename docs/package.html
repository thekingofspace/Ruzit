Package

Load arbitrary native shared libraries from disk and call their C-ABI functions with runtime-determined signatures. Unlike FFI — which requires the DLL to implement Ruzit's own ruzit_ffi_call/ruzit_ffi_free ABI — Package can talk to any C library: Win32 APIs, Steam, OpenVR, a shared library you pulled in via your build tooling, anything. It uses libffi under the hood to assemble argument lists at runtime. 

local Package = import("Package")

local lib = Package.Load("./mylib")        -- ./ implies exe directory
local add = lib:Bind("add_ints", Package.Types.Int32(), {
    Package.Types.Int32(),
    Package.Types.Int32(),
})
print(add(3, 4))                            -- 7

Where DLLs live (and don't)

Package.Load(path) only resolves paths relative to the executable's directory. ./mylib means "next to the running exe". The loader auto-appends the platform extension if you don't include one:

PlatformTried filenames for ./mylib
Windowsmylib.dll
Linuxlibmylib.so, then mylib.so
macOSlibmylib.dylib, then mylib.dylib

Use "./mylib.dll" or "./libmylib.so" when you want to pin a specific filename across platforms.

No traversal, no absolute paths, no Asset bundles. Package.Load rejects any path containing .., any absolute path, and anything that isn't relative to the exe directory. This is deliberate — native code runs with full process privileges, so loading is restricted to known-good locations you control at ship time. DLLs cannot live inside assets/ (they're encrypted inside a .managed bundle and not real files on disk); ship them next to the launcher via include = [...] in build.toml.

Package.Types

Type constructors. Each one works two ways:

  • Types.Int32() with no argument returns a type tag. Use it inside library:Bind(name, returnType, { argTypes... }) to declare the signature.
  • Types.Int32(42) with an argument returns a wrapped value. Pass it as an arg to a bound function instead of a bare number, and the runtime validates that the wrap's type matches the slot before coercing.

These styles compose — you can mix bare values and wrapped values in the same call: 

local Package = import("Package")
local T = Package.Types

local lib = Package.Load("./mylib")
local add = lib:Bind("add", T.Int32(), { T.Int32(), T.Int32() })

-- Style A: bare values, coerced per the declared signature.
print(add(3, 4))                  -- 7

-- Style B: explicit type-wrapped values. Errors at call time if a wrap
-- doesn't match the declared slot, useful for catching bugs early.
print(add(T.Int32(3), T.Int32(4)))   -- 7

-- Mixed:
print(add(T.Int32(3), 4))           -- 7

The "tag" returned by Types.X() is just a marker userdata with a .Name field; the "wrapped value" returned by Types.X(v) is a userdata with .Type and .Value fields. Neither pre-coerces — the conversion happens at call time, after the runtime has both the declared type and the value.

Bool semantics. Most Win32 / OS APIs use BOOL which is a 4-byte int (0 = false, anything else = true). Types.Bool() matches that convention — pass a Luau boolean and get a boolean back. If a specific API uses C99 _Bool (1 byte) instead, pass Types.UInt8() and convert manually.
About long. C's long is 4 bytes on Windows x64 but 8 bytes on Linux / macOS x64. The Long/ULong aliases map to ISize/USize, which is pointer-sized — that's 8 bytes on all 64-bit platforms. This is wrong for Windows. When you're calling into a Windows API that takes a 4-byte long, use Int32/UInt32 explicitly. For cross-platform code that uses Rust-style sizing or LP64 Unix, Long/ULong is what you want.

PackageHandle

.Alivebooleanread-only

False after :Unload().

.Sourcestringread-only

Absolute path the library was opened from.

lib:Bind(name, returnType, argTypes?) -> BoundFn method

Resolve name in the library's export table and prepare a libffi CIF for the given signature. argTypes is an optional array of Package.Types.* values; omit for a zero-argument function. Errors if the symbol doesn't exist or any type tag is invalid.

lib:Exports() -> { string } method

Parses the binary's export table and returns an array of exported symbol names. Windows uses the PE export directory; Linux walks .dynsym. macOS isn't implemented yet — you'll get an error there, but :Bind by name still works. Note that signatures are not discoverable — you only get names. You're expected to know what each function takes / returns from its header / docs.

lib:Unload()method

Close the library handle. Any subsequent :Bind errors; any pre-existing BoundFns also start erroring on call.

BoundFn

.Name / .Arity / .ReturnType / .ArgTypesread-only

Introspection — the symbol name, number of args, return type as a string, and the array of arg type strings.

fn(...) -> any callable

Blocking call. Coerces every arg against its declared type, hands them to libffi, and returns the result (or nil for Void). The Luau thread blocks for the duration of the C function — fine for fast pure compute or quick syscalls, bad for anything that does network I/O or waits on a mutex. For those, use :Async.

fn:Call(...) -> any method

Same as fn(...) — provided as an explicit method when you'd rather not use the call metamethod.

fn:Async(...) -> PackagePromise method

Spawns a worker OS thread that performs the call. The Luau thread doesn't block — the worker delivers the result via the engine's completion queue, drained each frame, which fires :AndThen / :Catch callbacks and wakes any pending :Await. Args are snapshotted before the spawn, so the Luau side can drop references freely.

PackagePromise

.Done / .Resolved / .Rejectedread-only

Booleans reflecting the promise's current state. Useful for polling without yielding.

promise:AndThen(callback) -> PackagePromise method

Register a success callback. If the promise is already resolved, the callback fires immediately on the calling thread; otherwise it fires when the worker completes and the engine drains the queue (per-frame). Returns the same promise so you can chain :AndThen(...):Catch(...).

promise:Catch(callback) -> PackagePromise method

Register an error callback. Fires once with the error string if the worker panicked or the call mid-flight saw the library get unloaded. An async call never throws on the Luau side — uncaught errors stay confined to the worker thread and are reported through this callback.

promise:Await() -> any method

Block the current Luau coroutine until the promise settles, then return the resolved value (or raise the error from a rejection). Internally yields the coroutine; the engine's heart loop resumes it when the worker delivers a result.

Patterns

Calling a Win32 API

local Package = import("Package")

-- kernel32.dll is in the system PATH on Windows, so it can be loaded
-- by name without a full path. On Linux you'd Load("./libc") and adjust.
local kernel32 = Package.Load("./kernel32")

local GetTickCount = kernel32:Bind("GetTickCount", Package.Types.UInt32())
print(GetTickCount())                                -- ms since boot

local Sleep = kernel32:Bind("Sleep", Package.Types.Void(), {
    Package.Types.UInt32(),
})
Sleep(100)                                          -- blocking 100ms — careful

Async — keep the game responsive

local heavy = lib:Bind("do_heavy_compute", Package.Types.Double(), {
    Package.Types.UInt32(),
})

heavy:Async(100000)
    :AndThen(function(result)
        print("finished:", result)
    end)
    :Catch(function(err)
        warn("heavy compute failed: " .. err)
    end)

-- Or yield-style inside a coroutine:
local Task = import("Task")
Task.Spawn(function()
    local result = heavy:Async(100000):Await()
    print("finished:", result)
end)

Listing what's available

local lib = Package.Load("./steam_api64")

for _, name in lib:Exports() do
    if name:find("Achievement") then
        print(name)
    end
end

-- Once you've found one you want, declare the signature manually
-- (the export table doesn't carry argument types).
local init = lib:Bind("SteamAPI_Init", Package.Types.UInt32())
print(init())                                -- 1 = success

Limitations of this build

  • Scalar args only. No struct args / returns, no array args, no function-pointer callbacks (DLL → Luau). Each will need separate libffi work; the existing scalar / pointer / cstring set covers ~90% of typical OS and SDK APIs.
  • No variadics. printf-style functions can't be bound directly. Use a typed wrapper in your DLL instead.
  • Calling convention is the platform default. On Windows x64 that's the standard x64 ABI. stdcall / fastcall on x86 aren't currently selectable — Windows x64 only.
  • macOS export enumeration not implemented. :Bind by name still works; only :Exports() errors there in this build.
  • UB is on you. A mismatched signature, a wrong arg type, or a stale pointer crashes the process with no recovery path — this is C-ABI calling, not a sandbox. Test signatures carefully.
