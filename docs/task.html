Task

Time-driven scheduler. Defer one-shot work to a future tick, fire callbacks at fixed intervals, or schedule a named task you can later cancel or reschedule. All callbacks run on the engine's main thread between heart ticks; errors are caught and printed without crashing. 

local Task = import("Task")

-- Fire-and-forget on next tick.
Task.Spawn(function() print("hello") end)

-- Fire once after 3 seconds.
Task.Delay(3, function() save_progress() end)

-- Repeating tick that we can later retune or cancel.
Task.Repeat("autosave", 60, function() autosave() end)
Task.SetInterval("autosave", 10) -- now every 10s
Task.Cancel("autosave")

Task API

Coroutine-based one-shots

All three of these run their callback on a fresh Lua coroutine, so the callback can call Task.Wait to sleep without blocking the rest of the engine. They each return the underlying thread, which you can hand to Task.Cancel if you need to abort before it fires.

Task.Spawn(fn) → thread

Create a coroutine wrapping fn and resume it immediately. If fn never yields it runs synchronously to completion before Spawn returns; if it yields (via Task.Wait) the scheduler resumes it later. Errors inside fn are caught and printed.

Task.Defer(fn) → thread

Run fn at the end of the current tick's scheduler pass — after every Spawn / Delay / Schedule / Repeat that's due this tick. Use it when you want to schedule work that should observe everyone else's this-tick mutations: mutate state in a signal handler, then Defer the dependent recompute so other handlers on the same signal still see pre-mutation state. If a Defer'd callback calls Defer again, the new one runs on the next tick (not the current one), so you can't accidentally infinite-loop within a single frame.

Task.Delay(seconds, fn) → thread

Run fn once after seconds real time (clamped to ≥ 0). The returned thread can be canceled via Task.Cancel(thread) before it fires.

Task.Wait(seconds?)

Yield the current coroutine for seconds real time, then resume it on a future scheduler pump. The engine runs every script in a coroutine — the entry script, signal handlers, and Spawn / Delay / Defer threads all already qualify — so Wait is callable anywhere, no setup needed. Pass nil or 0 to yield until the next pump. 

-- At top level of any script:
play_intro()
Task.Wait(1.5)
show_menu()
The whole engine runs in coroutines. Your entry script (Main.luau) is launched on a coroutine; every signal handler (:Connect callbacks) gets its own fresh coroutine when the signal fires. That's why Task.Wait "just works" everywhere — you're never on the bare main thread.
Spawn vs Defer. Spawn resumes its coroutine immediately (synchronously). Defer queues the coroutine and resumes it at the end of the current tick, AFTER every other due task has fired. Pick Defer when ordering against other reactive code matters (e.g. you want every observer of an event to fire before your follow-up logic runs).

Scheduled (named one-shots)

Task.Schedule(id?, seconds, fn) → string

Run fn once after seconds. Pass nil for id to auto-generate one. Returns the id (whether you supplied it or not), so you can hold onto it for Reschedule / Cancel. Reusing an existing id replaces and cancels the previous schedule under that id.

Task.Reschedule(id, seconds) → boolean

Reset the timer for an existing scheduled task to fire seconds from now. Returns true if id was an active schedule (and was successfully rescheduled), false if no such id exists.

Repeatable (named ticks)

Task.Repeat(id?, interval, fn) → string

Run fn repeatedly every interval seconds. Pass nil for id to auto-generate one. Returns the id. Reusing an existing id replaces and cancels the previous repeat under that id. Errors inside fn are caught + logged; the repeat keeps firing.

Task.SetInterval(id, interval) → boolean

Change the firing rate of an existing repeat. The next fire happens interval seconds from now (i.e. the timer resets, you don't have to wait for the current cycle to finish). Returns true if id existed.

Management

Task.Cancel(target) → boolean

Cancel a task by either a string id or a thread reference.

  • string — cancel a Schedule or Repeat registered under that id.
  • thread — the thread returned by Spawn / Delay / Defer. The thread is marked for cancellation; on the next scheduler pump it's skipped instead of being resumed, and its registration is cleared. Calling Cancel on a thread that's already running synchronously has no effect (you can't preempt code that hasn't yielded yet).

Returns true if something matching was canceled, false otherwise. Safe on unknown ids / unrelated threads. 

local handle = Task.Delay(5, function() save() end)
-- ...later, e.g. user pressed cancel:
Task.Cancel(handle)
Task.Exists(id) → boolean

True if a Schedule or Repeat with this id is currently active.

Task.TimeLeft(id) → number?

Seconds until the named task next fires, or nil if no task with that id exists. For Repeat, this is the time until the next tick. Useful for HUD timers.

Single id space. Schedule and Repeat share one id namespace. If you Schedule "x" and then Repeat "x", the schedule is canceled and replaced by the repeat (and vice versa). Cancel / Exists / TimeLeft all consult both sets.
Tasks tick on the engine's heart pump. Timing is "no-earlier-than" — if your frame loop stalls for 100 ms, all due tasks fire on the first tick afterward. Repeats catch up with one fire per pump (not many) so a stalled repeat won't emit a burst when the loop recovers.
