Task

Time-driven scheduler. Defer one-shot work to a future tick, fire callbacks at fixed intervals, or schedule a named task you can later cancel or reschedule. All callbacks run on the engine's main thread between heart ticks; errors are caught and printed without crashing. 

local Task = import("Task")

-- Fire-and-forget on next tick.
Task.Spawn(function() print("hello") end)

-- Fire once after 3 seconds.
Task.Delay(3, function() save_progress() end)

-- Repeating tick that we can later retune or cancel.
Task.Repeat("autosave", 60, function() autosave() end)
Task.SetInterval("autosave", 10) -- now every 10s
Task.Cancel("autosave")

Task API

Anonymous one-shots

Task.Spawn(fn)

Run fn once on the next engine tick. The caller doesn't block; fn runs after the rest of the current frame's work. Errors inside fn are caught and printed; they don't crash the engine. Fire-and-forget — no id, no cancel.

Task.Delay(seconds, fn)

Run fn once after seconds real time (clamped to ≥ 0). No id — if you need cancel / reschedule, use Schedule with an id instead.

Scheduled (named one-shots)

Task.Schedule(id?, seconds, fn) → string

Run fn once after seconds. Pass nil for id to auto-generate one. Returns the id (whether you supplied it or not), so you can hold onto it for Reschedule / Cancel. Reusing an existing id replaces and cancels the previous schedule under that id.

Task.Reschedule(id, seconds) → boolean

Reset the timer for an existing scheduled task to fire seconds from now. Returns true if id was an active schedule (and was successfully rescheduled), false if no such id exists.

Repeatable (named ticks)

Task.Repeat(id?, interval, fn) → string

Run fn repeatedly every interval seconds. Pass nil for id to auto-generate one. Returns the id. Reusing an existing id replaces and cancels the previous repeat under that id. Errors inside fn are caught + logged; the repeat keeps firing.

Task.SetInterval(id, interval) → boolean

Change the firing rate of an existing repeat. The next fire happens interval seconds from now (i.e. the timer resets, you don't have to wait for the current cycle to finish). Returns true if id existed.

Management

Task.Cancel(id) → boolean

Cancel a Schedule OR Repeat by id. Returns true if something with that id was active and got canceled. Safe on unknown ids (returns false).

Task.Exists(id) → boolean

True if a Schedule or Repeat with this id is currently active.

Task.TimeLeft(id) → number?

Seconds until the named task next fires, or nil if no task with that id exists. For Repeat, this is the time until the next tick. Useful for HUD timers.

Single id space. Schedule and Repeat share one id namespace. If you Schedule "x" and then Repeat "x", the schedule is canceled and replaced by the repeat (and vice versa). Cancel / Exists / TimeLeft all consult both sets.
Tasks tick on the engine's heart pump. Timing is "no-earlier-than" — if your frame loop stalls for 100 ms, all due tasks fire on the first tick afterward. Repeats catch up with one fire per pump (not many) so a stalled repeat won't emit a burst when the loop recovers.
