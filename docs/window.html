Window

Open and control the application window. One per process. Built on winit, so the same code drives Win32 / X11 / Wayland / AppKit. 

local Window = import("Window")

local win = Window.Open({
    title  = "My Game",
    width  = 1280,
    height = 720,
    resizable = true,
})

win.OnFocus:Connect(function() print("focused") end)
win:BindToClose(function() print("saving...") end)

Window API

Window.Open(opts?) -> WindowHandle

Open the application window. Only one is allowed at a time; calling twice throws.

WindowOptions

All fields are optional. Defaults: 800 × 600, decorated, resizable, visible, with the executable name as the title.

titlestring, caption shown in the title bar / taskbar.
width / heightnumber, initial inner-area size in logical pixels.
min_width / min_heightOptional minimum-size constraint.
max_width / max_heightOptional maximum-size constraint.
fullscreenExclusive fullscreen. Most games should prefer borderless.
borderlessBorderless fullscreen, covers the OS taskbar; Alt+Tab works cleanly.
resizableDefault true.
maximizedStart maximized.
visibleDefault true. Set false if you need to preload before showing.
transparentPer-pixel alpha. Requires a compositor.
always_on_topPin above other windows. Ignored in fullscreen / borderless.
iconImageAsset for the title-bar / taskbar icon. PNG works best.

Signals

Per-property signals, one per kind of state change. Each fires only when its specific property actually changes. See Deprecated for the older fan-out Changed signal.

Geometry

.SizeChangedSignal<number, number>read-only

Inner-area size changed. Fires with (width, height) in logical pixels. Triggered by the OS Resized event,user drags, window-manager forces, or the engine's own :Resize() being applied.

.PositionChangedSignal<number, number>read-only

Outer position changed. Fires with (x, y) — screen coords of the top-left. Triggered by the OS Moved event.

.ScaleFactorChangedSignal<number>read-only

DPI / HiDPI scale factor changed. Fires when the window moves between monitors of different DPI. Arg: new scale (e.g. 1.0, 1.5, 2.0).

Focus

.FocusChangedSignal<boolean>read-only

Window gained or lost keyboard focus. Arg: now-focused boolean. Symmetrical pair of OnFocus / OnUnfocus rolled into one signal so a single handler can branch on the value.

.OnFocusSignal<>read-only

Fires when the window gains keyboard / mouse focus.

.OnUnfocusSignal<>read-only

Fires on focus loss. Useful for releasing mouse lock, pausing, etc.

win:GetViewport()-> Cameramethod

The 3D camera for this window. The same singleton is returned on every call — writes to .CFrame, .FOV, etc., as well as :LinkTo / :Follow, all share state. See Camera below for the full API.

Camera

There is one Camera per window, accessed via win:GetViewport(). It carries the projection (FOV / near / far) and the world-space CFrame the renderer reads each frame. 

local Window = import("Window")
local win    = Window.Open({ title = "Game", width = 1280, height = 720 })
local cam    = win:GetViewport()
cam.CFrame = CFrame.new(Vector.new(0, 5, 10), Vector.new(-0.2, 0, 0))
cam.FOV  = 75
cam.Near = 0.1
cam.Far  = 2000

Properties

.CFrameCFrame

World pose. .Position is the eye, .Rotation aims the look vector. Writes from script work normally until you call :Follow/:LinkTo, after which the engine overwrites this every frame.

.FOVnumber

Vertical field of view in degrees. Clamped to 1..179.

.Near / .Farnumber

Clipping plane distances in studs.

.IsLinkedbooleanread-only

True while :Follow / :LinkTo is active.

Following a target

Rather than writing cam.CFrame from a per-frame loop, let the engine drive it. After physics + controllers tick each frame, the engine pulls the target's CFrame, composes the offset (in target-local space), runs the optional callback, and writes the result back to cam.CFrame. Three valid targets:

  • BasePart — for anchored set pieces or pre-physics rigs.
  • PhysicsObject — tracks the simulated body's pose.
  • Controller — the typical first-/third-person target.
cam:Follow(target) method

Shortcut for :LinkTo(target) with no offset and no callback — the camera CFrame is set to the target's CFrame each frame. Replaces any existing link. Accepts BasePart, PhysicsObject, or Controller. 

cam:Follow(player)
cam:LinkTo(target, opts?) method

Same idea as :Follow, plus a target-local offset and an optional per-frame callback. opts can be either:

  • A table { Offset = CFrame?, Callback = function? }.
  • A bare CFrame (treated as Offset).
  • A bare function (treated as Callback).

A second :LinkTo call replaces the previous link entirely.

Callback signature. function(dt: number, baseCFrame: CFrame) -> CFrame?. dt is the same delta-time threaded through physics. baseCFrame is the target's CFrame already composed with the offset — you can return it unmodified, return nil to accept it as the final pose, or return a new CFrame to layer per-frame effects (head-bob, breathing, recoil, lean, screen-shake). 

-- third-person follow with a 1-stud-up eye offset and breathing
cam:LinkTo(player, {
    Offset = CFrame.new(Vector.new(0, 1.5, -6)),
    Callback = function(dt, base)
        local t   = os.clock()
        local bob = math.sin(t * 2.1) * 0.04
        return CFrame.new(
            base.Position + Vector.new(0, bob, 0),
            base.Rotation
        )
    end,
})

-- first-person with mouse-driven look passed through the controller
cam:LinkTo(player, CFrame.new(Vector.new(0, 1.7, 0)))

-- bare-function form: no offset, just a tween/shake layer
cam:LinkTo(target, function(dt, base)
    return shake:Apply(base, dt)
end)
cam:Unlink() method

Detach. The camera CFrame stops updating until script writes to it or calls :Follow/:LinkTo again. .IsLinked flips to false.

cam:SetOffset(offset) method

Swap the offset CFrame on the active link without re-targeting. No-op when not linked.

cam:SetLinkCallback(fn?) method

Replace the per-frame callback on the active link. Pass nil to clear it (the link itself stays active — the camera just stops post-processing). Errors when no link is active.

When the link runs

The link is evaluated inside heart::run_loop, immediately after physics::tick and before animation / drawable / GUI ticks. The order is intentional: Controllers and PhysicsObjects finish their integration step, write their final CFrames to their BaseParts, and only then does the camera read them — so a third-person camera never lags one frame behind the body it follows.

VR takeover. When VR.LinkVRView() is active, the engine overwrites cam.CFrame each frame with the composed BodyCFrame + HeadCFrame from the headset. The :LinkTo path is bypassed entirely while VR is bound; unlink VR first if you want to drive the camera yourself.

Deprecated

APIs being phased out. Code written against pre-3.3 docs goes here.

The fan-out Changed signal

Older versions exposed a single WindowHandle.Changed signal that fired with a property-name string for every kind of state change. As of v3.3 it's superseded by the per-property signals above (SizeChanged, PositionChanged, TitleChanged, etc.), typed and fired only when the specific property changes.

VersionStatus
3.3 and earlier (current) Changed exists alongside the new per-property signals. Existing code keeps working without changes.
3.4 and later Changed is frozen. It keeps firing for the four OS events it always fired for (Resized, Moved, Focused, ScaleFactor), but it won't gain coverage of any new window state, those will only show up as new per-property *Changed signals. Existing connections keep working; new behaviour goes through the typed signals.

What Changed actually fired

For backward-compat reference: Changed only ever fired for engine-side OS events, not for Lua-side setter calls (despite earlier doc claims that listed "Title" / "Fullscreen" / etc. as possible values).

change nameextra args3.2+ replacement
"Resized"width, heightSizeChanged
"Moved"x, yPositionChanged
"Focused"booleanFocusChanged (or OnFocus/OnUnfocus)
"ScaleFactor"scaleScaleFactorChanged

Migration

Pre-3.23.2+
 
win.Changed:Connect(function(name, ...)
    if name == "Resized" then
        local w, h = ...
        layout(w, h)
    elseif name == "Focused" then
        if select(1, ...) then resume() end
    end
end)
 
win.SizeChanged:Connect(function(w, h)
    layout(w, h)
end)

win.FocusChanged:Connect(function(focused)
    if focused then resume() end
end)
If you were relying on setter-side fires. Old docs incorrectly listed "Title", "Fullscreen", "Maximized", etc. as Changed values. The engine never actually fired those, and now that Changed is frozen as of 3.4 they never will. The new TitleChanged / FullscreenChanged / MaximizedChanged signals are the first observable way to react to those transitions, so this isn't a regression: it's a capability you didn't have before.
