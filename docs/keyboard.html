Keyboard

Key events and snapshot queries. InputChanged fires for every press / release; IsKeyDown is a free poll. 

local Keyboard = import("Keyboard")

local jump_id = Keyboard:GetKeyId("Space")

Keyboard.InputChanged:Connect(function(id, name, state)
    if id == jump_id and state == "Begin" then
        player:Jump()
    end
end)

if Keyboard:IsKeyDown("w") then ... end

Keyboard API

.InputChangedSignal<number, string, "Begin" | "End">read-only

Fires with (id, name, state). state is "Begin" on press and "End" on release. See Deprecated if you're migrating from a pre-3.2 codebase.

Keyboard:IsKeyDown(key) → boolean method

Pass either the name string ("w", "Space") or the numeric id from InputChanged / GetKeyId. Numeric ids are stable across runs and faster to compare.

Keyboard:GetKeyId(name) → number method

Resolve a name string to its stable numeric id. Internally FNV-1a-32 of the name; cache the result if you compare keys in a hot loop.

Deprecated

APIs removed or changed since the older shape. Code written against pre-3.2 docs goes here.

Pre-3.2: InputChanged with pressed boolean

Older versions fired InputChanged with the legacy (id, name, pressed, state) signature, a boolean duplicating the state string. As of Ruzit 3.2 the boolean is gone. Any version 3.2 or newer fires (id, name, state) only.

Pre-3.23.2+
 
Keyboard.InputChanged:Connect(function(id, name, pressed)
    if name == "Space" and pressed then
        player:Jump()
    end
end)
 
Keyboard.InputChanged:Connect(function(id, name, state)
    if name == "Space" and state == "Begin" then
        player:Jump()
    end
end)
Migration note. The boolean was the third argument; the State string took its place. Replace (id, name, pressed) with (id, name, state), and any reference to pressed / not pressed with state == "Begin" / state == "End".

Key names

Names follow winit conventions, mostly the literal character for printables and CamelCase for named keys.

GroupExamples
Letters"a" through "z" (lowercase)
Digits"0" through "9"
Punctuation".", ",", ";", "'", etc. (literal characters)
Whitespace"Space", "Tab", "Enter", "Backspace"
Modifiers"ShiftLeft", "ShiftRight", "ControlLeft", "ControlRight", "AltLeft", "AltRight", "SuperLeft", "SuperRight"
Function keys"F1" through "F24"
Arrows"ArrowUp", "ArrowDown", "ArrowLeft", "ArrowRight"
Navigation"Home", "End", "PageUp", "PageDown", "Insert", "Delete"
Special"Escape", "PrintScreen", "ScrollLock", "Pause", "CapsLock", "NumLock"
Numpad"Numpad0" through "Numpad9", "NumpadAdd", "NumpadSubtract", "NumpadMultiply", "NumpadDivide", "NumpadDecimal", "NumpadEnter"
Layout-independent. Names refer to physical keys. "w" is the key in the W position on a US QWERTY layout, regardless of what character a French AZERTY user types when pressing the same key. Use this for movement bindings; for text input, the engine surfaces typed characters separately.
