IO

File system access. One-shot helpers for the common case (read, write, append), open for streaming. All paths are interpreted relative to Ruzit's current root unless absolute. 

local IO = import("IO")

local save = IO.read("saves/slot1.json")
IO.write("saves/slot1.json", tostring(os.time()))

IO API

One-shot helpers

IO.read(path) → string

Open, read everything, close. Throws if the file can't be opened. Returns the raw bytes, UTF-8 decoding is up to the caller.

IO.write(path, content)

Truncate-write. Creates the file if missing; replaces contents entirely if it exists.

IO.append(path, content)

Like write, but adds to the end without truncating.

IO.exists(path) → boolean

True for files OR directories.

IO.remove(path)

Delete a file. No-op if the file doesn't exist; throws on permission / "is a directory" errors.

IO.mkdir(path)

Recursively create the directory chain. No-op if it already exists.

IO.list(path) → { string }

List directory entries (names only, not full paths). Order is OS-defined.

IO.getpath(path) → string

Resolve a (possibly relative) path against Ruzit's current root and return the absolute form.

System paths

Read-only properties resolved per-OS at first import. Linux uses XDG conventions ($XDG_CONFIG_HOME, $XDG_DATA_HOME, $XDG_CACHE_HOME), Windows uses Known Folders, macOS uses ~/Library. Each can be nil if the OS doesn't expose that location (rare); always nil-check before using.

local IO = import("IO")

-- Pick a save dir that respects the platform's conventions.
local root = (IO.AppData or IO.Home or IO.Temp)
    .. IO.Separator .. "MyGame"
IO.mkdir(root)
IO.write(root .. IO.Separator .. "save.json", payload)
Don't write your save data to IO.Documents. On Windows it's a synced folder (OneDrive / Documents Library) and users will get sad when their saves grow large or sync slowly. Use IO.AppData for game-managed state and IO.LocalAppData for cache / large blobs that don't need to roam between machines.

Streaming open

IO.open(path, mode?) → IOHandle

Open a streaming handle. mode follows fopen conventions:

ModeBehavior
"r" (default)Read-only. Throws if missing.
"w"Truncate + write. Creates the file if missing.
"a"Append. Creates the file if missing.
"r+"Read + write, no truncate.
"w+"Read + write, truncate.
"a+"Read + append.

IOHandle

Returned by IO.open. Wraps an OS file descriptor.

handle:read(format?) → string method

Read from the current position. format defaults to "*a".

formatEffect
"*a" (default)Read everything remaining.
"*l"One line, newline stripped.
"*L"One line, including the newline.
"*n"Read a Lua-formatted number.
N (number)Read up to N bytes.
handle:write(content) method

Append content at the file's current position. Use IO.write for one-shot writes; only reach for an IOHandle when you need streaming.

handle:close() method

Flush + release the OS handle. Idempotent, calling twice is a no-op.

handle:path() → string method

The path that was passed to IO.open, normalised to absolute form.
