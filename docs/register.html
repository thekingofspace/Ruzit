Register

Named shared tables. Two scripts that have never seen each other can coordinate by agreeing on a name — Register.new("foo") always returns the same table for the same name across the entire Lua state. 

-- script_a.luau
local Register = import("Register")
local world = Register.new("world")
world.gravity = 9.8
world.players = {}

-- script_b.luau (loaded later, never imports script_a)
local Register = import("Register")
local world = Register.new("world")
print(world.gravity)         -- 9.8
table.insert(world.players, "Eve")

Register API

Register.new(name) → table

Get (or create) the named register. First call with a given name creates a fresh empty table; every subsequent call with the same name returns the same instance, regardless of which script asks. Mutate the table normally — every other script holding a handle sees the additions and deletions.

Register.Has(name) → boolean

True if a register with this name already exists. Useful for "first-script-in-wins" seeding patterns where the first script bootstraps and later scripts skip-or-attach.

Register.Drop(name) → boolean

Release the named register. Existing handles already returned by new keep working; freshly-fetched ones get a new empty table. Returns true if the register existed before this call.

Register.Names() → { string }

Every currently-registered name. Handy for debug overlays and for snapshotting the world for save files.

Patterns

Cross-script event bus

local Register = import("Register")
local Signal = import("Signal")

local bus = Register.new("events")
bus.player_died = bus.player_died or Signal.new()
bus.level_loaded = bus.level_loaded or Signal.new()

-- Anywhere else in the codebase:
local bus = Register.new("events")
bus.player_died:Connect(function(name) print(name .. " died") end)

Lazy seeding

local cfg = if Register.Has("config") then
    Register.new("config")
else
    local seed = Register.new("config")
    seed.audio_volume  = 0.7
    seed.master_volume = 1.0
    seed
end
Scope. Registers are scoped to a single Lua state — the main runtime. They aren't shared with Actor workers (those have isolated states) and they don't persist across runs. For cross-process state use Steam Cloud or IO; for cross-actor state pass values explicitly via actor:Push.

For loading scripts from arbitrary disk paths (mods, user-content, hot-loaded plugins) see the global load function under Tooling > Globals.
