DrawableImg & CanvasBuffer

CPU-mutable pixel buffers you draw to with simple shape primitives. A DrawableImg is a live texture: assign it to a BasePart.Texture and any draw call shows up on the next frame. A CanvasBuffer is a scratch buffer with the same draw methods, used to batch many edits into a single GPU re-upload. 

local GUI        = import("GUI")
local Renderable = import("Renderable")
local Color3     = import("Primitives").Color3

Picking the right texture source

If you want…Use
A static image authored offline (PNG, JPG, …) Asset.GetAsset("Image", "…")
A live composition of GUI primitives (text + image layers, like an in-world sign) DynImg
To procedurally draw with shape primitives (paint, plot, scribble, render gameplay state into a texture) DrawableImg (this page)

All three plug into the same slot — part.Texture = … — and the texture refreshes automatically on the next frame for the live variants.

Conceptual model

  • A DrawableImg owns a fixed-size RGBA8 buffer plus a version counter. Every drawing method bumps the version, the renderer notices and re-uploads to the GPU before the next frame.
  • Drawing methods alpha-blend onto the existing pixels. Fill / Clear / WritePixel overwrite instead.
  • A CanvasBuffer is the same buffer layout without the version + GPU wiring. Use it as a scratch pad: stage many draws, then commit in one shot via buffer:Apply(drawable, x, y). The drawable's version bumps once, GPU re-uploads once.

Coordinates & color

  • Top-left is (0, 0); x increases right, y increases down.
  • All coordinates are integer pixels. Floats are coerced via Lua-to-int conversion. Out-of-bounds pixels are clipped silently — no error, no wrap.
  • Colors are Color3 (RGB in 0..1). The optional transparency arg is 0..1 with 0 = fully opaque, 1 = fully transparent — matches GUI primitives.

Factories

GUI.DrawableImg(width, height) → DrawableImg

Build a fresh, fixed-size mutable image. Pixels start at (0, 0, 0, 0) (transparent black). Not cached — each call returns a new instance with its own buffer and texture id.

GUI.CanvasBuffer(width, height) → CanvasBuffer

Build a scratch buffer of the given size. Same draw methods as DrawableImg; commit to a real drawable via buffer:Apply(target, x?, y?).

Drawing methods

All of these exist on both DrawableImg and CanvasBuffer.

obj:WritePixel(x, y, color, transparency?)

Overwrite a single pixel. Doesn't blend with what was there. Default transparency 0.

obj:DrawRect(x, y, w, h, color, transparency?)

Alpha-blend a filled axis-aligned rectangle. obj:DrawCube(...) is a synonym — same method, same args. Pick whichever name reads better in your code.

obj:DrawLine(x0, y0, x1, y1, color, transparency?)

Bresenham line, one pixel thick, alpha-blended onto existing content.

obj:DrawCircle(cx, cy, radius, color, transparency?, filled?)

Outline circle by default (midpoint / Bresenham). Pass filled = true for a solid disc. radius = 0 draws a single pixel at (cx, cy).

obj:Fill(color, transparency?)

Overwrite every pixel with one color + alpha. Doesn't blend — this is your "reset to a solid color" call.

obj:Clear()

Reset every pixel to (0, 0, 0, 0) — fully transparent black. Equivalent to Fill(Color3.new(0, 0, 0), 1) but cheaper.

DrawableImg accessors

img:Width()→ number
img:Height()→ number
img:Source()→ string

Origin label, formatted as "<drawable:WxH>". Mirrors ImageAsset:Source so logging code that handles either kind doesn't have to special-case.

img:Pixels()→ string

Snapshot of the current RGBA8 buffer (Width * Height * 4 bytes, row-major, top-left origin). Useful for screenshots, save-state blobs, or hand-rolled image processing.

img:IsAlive()→ boolean

False after :Destroy(). Drawing methods still accept calls (and bump the version) but the visible result for any consuming part is transparent black.

img:Apply(buffer, atX?, atY?)

Convenience: alpha-blend a CanvasBuffer onto this drawable at the given offset (default (0, 0)). Equivalent to buffer:Apply(img, atX, atY).

img:Destroy()

Mark dead and zero the pixels. Drop your Lua reference, and clear the part's .Texture if it still points at this drawable, to actually free the buffer + GPU texture.

CanvasBuffer accessors

buffer:Width()→ number
buffer:Height()→ number
buffer:Pixels()→ string

Snapshot the buffer the same way DrawableImg:Pixels does. Note that a CanvasBuffer never goes to the GPU on its own.

buffer:Apply(target, atX?, atY?)

Alpha-blend the buffer onto the target DrawableImg at (atX, atY). Bumps the drawable's version exactly once, so the GPU re-upload happens in a single shot even though the buffer was mutated dozens of times. The buffer itself is unchanged after Apply — you can keep drawing into it and Apply again.

Lifecycle & performance

  • Not cached. Every GUI.DrawableImg(...) creates a fresh buffer and a unique texture id. There's no de-duplication across calls; you get back a distinct instance.
  • Per-call uploads. Every drawing method on DrawableImg bumps the buffer's version, which triggers queue.write_texture the next time the renderer ticks. For one or two draws per frame this is fine; for hundreds, stage in a CanvasBuffer and Apply once.
  • Cleanup. Drop the Lua reference and clear any consuming part's .Texture; the renderer's eviction sweep then drops the cached GPU texture. :Destroy() zeros the pixels immediately but doesn't itself free the buffer — Arc refcounting handles that.
  • CPU cost. Drawing is straightforward software rasterization. DrawCircle(filled=true) on a 200-pixel-radius disc paints ~125k pixels per call — reasonable per frame, expensive per tick if done dozens of times. Profile with Debug.Frame if it shows up.

Recipes

Paint a face onto a cube

local face = GUI.DrawableImg(128, 128)
face:Fill(Color3.new(1, 0.9, 0.7))                          -- skin tone
face:DrawCircle(42, 48, 8, Color3.new(0, 0, 0), 0, true)  -- left eye
face:DrawCircle(86, 48, 8, Color3.new(0, 0, 0), 0, true)
face:DrawLine(40, 90, 88, 90, Color3.new(0.6, 0, 0))       -- mouth

local head = Renderable.BasePart("Cube")
head.Texture = face

HUD health bar (re-blit each tick)

local bar = GUI.DrawableImg(256, 32)

local function draw_bar(hp01)
    bar:Fill(Color3.new(0.1, 0.1, 0.1))
    local w = math.floor(252 * hp01)
    bar:DrawRect(2, 2, w, 28, Color3.new(0.9, 0.2, 0.2))
    bar:DrawRect(2, 2, math.min(8, w), 28, Color3.new(1, 1, 1), 0.5) -- hilite
end

draw_bar(1)
hud_part.Texture = bar

-- Each time HP changes:
draw_bar(player.HP / player.MaxHP)
-- 4 draw calls = 4 version bumps in a row, but the GPU only re-uploads
-- once per frame, so this is fine.

Mini-map dot plot (batched via CanvasBuffer)

local minimap = GUI.DrawableImg(256, 256)
local scratch = GUI.CanvasBuffer(256, 256)

local function redraw_minimap(entities)
    scratch:Fill(Color3.new(0.05, 0.05, 0.05))
    for _, e in entities do
        local px = math.floor((e.X / WORLD_W) * 256)
        local py = math.floor((e.Z / WORLD_D) * 256)
        scratch:DrawCircle(px, py, 3, e.Color, 0, true)
    end
    scratch:Apply(minimap)        -- single GPU re-upload, no matter how many entities
end

minimap_part.Texture = minimap
Process.Heartbeat:Connect(function() redraw_minimap(world.entities) end)

Pixel scribble in response to clicks

local board = GUI.DrawableImg(512, 512)
board:Fill(Color3.new(1, 1, 1))

canvas_part.Texture = board

local Mouse = import("Mouse")
local last
Mouse.Move:Connect(function(pos)
    if Mouse.IsDown("Left") and last then
        board:DrawLine(last.X, last.Y, pos.X, pos.Y, Color3.new(0, 0, 0))
    end
    last = pos
end)

Caveats

  • No anti-aliasing. DrawLine and DrawCircle are pixel-snapped Bresenham plots, so diagonal edges step. If you need smooth edges, supersample at higher resolution and downscale, or use a pre-baked AA sprite.
  • No text drawing on the buffer itself. Build a text glyph in a DynImg layer (which uses fontdue's rasterizer) if you need labels.
  • No transforms. Coordinates are absolute pixels — rotation / scaling on the source must be done by your own code or via a 3D shader on the consuming part.
  • Single texture format: 8-bit per channel sRGB RGBA. High-precision content (HDR, single-channel height-fields) needs a different path.
