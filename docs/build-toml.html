build.toml

Project metadata and build settings. Lives at the root of every project next to Main.luau. Read by ruzit test and ruzit build; ignored at runtime in packaged games.

Example

name      = "My Game"
version   = "0.1.0"
creator   = "Studio Name"

exe-name  = "MyGame"
exe-icon  = "logo.ico"
exe-windowed = true

"File Type" = "Relative"
compress-scripts = true
compress-assets  = true
shard-assets     = false

steam-app-id = 480

include = [
    "steam_appid.txt",
    "third-party/openvr_api.dll",
    "localization/",
]

Fields

name string

Display name shown in the engine banner and in the launcher's metadata. Defaults to the project folder name.

version string

Free-form version string (use semver if it suits you). Surfaced via Steam rich presence and crash logs.

creator string

Studio / author name. Shown in the launcher banner alongside version.

exe-name string

Filename for the launcher executable. "MyGame" yields MyGame.exe on Windows and MyGame on Linux/macOS. Defaults to the entry-script stem.

exe-icon string

Path (relative to build.toml) of an .ico file embedded in the Windows launcher. Ignored on Linux/macOS, those platforms set the icon via .desktop files / .app bundles, not by editing the binary.

exe-windowed boolean

On Windows, sets the PE subsystem to GUI (no console window spawns). Pass --console at the command line if you ever need stdout from a windowed launcher. No effect on other platforms.

"File Type" "Relative" | "Global"

Module-resolution mode for require(). In Relative mode (the default) paths are resolved against the calling script's directory; in Global mode they're rooted at the project root regardless of where require is called.

compress-scripts boolean

Zstd-compress every script before bundling. Shrinks .scripts.managed by ~3× on typical Lua. Default true.

compress-assets boolean

Zstd-compress every asset before bundling. Skips already- compressed formats (PNG, OGG, JPG) at runtime since the gain is negligible. Default true.

shard-assets boolean

Split the asset bundle into ~64 MB shards. Recommended for large games where patches should re-download only the shards that changed. Produces <id>.assets.shard0001.managed files plus a <id>.assets.manifest.managed index.

bytecode boolean

Compile every .luau / .lua file to Luau bytecode at build time and ship the bytecode in place of source. Faster startup (no parse/compile at runtime), smaller binary size, and source is no longer recoverable from the .scripts.managed file. Default false.

Trade-off — error messages. Runtime errors still report line numbers (the engine compiles with debug_level = 1 so backtraces work), but the engine no longer has the source text on hand to print the actual offending line in error output — you'll see Main.luau:42: ... instead of the full local x = bad_thing <-- here snippet. Keep this off during active development; flip it on for release builds where size and load speed matter more than in-the-loop debugging.

Mixing is fine: a bytecode-compiled package can require a non-bytecode package (and vice versa), and load() still works on .luau source files dropped next to the exe. Each chunk is decoded independently.

steam-app-id number

Your Steamworks AppID. The launcher passes this into the Steamworks SDK at startup so achievements / DLC / Workshop calls map to the right game. Use Valve's spacewar AppID (480) for testing.

include { string }

Non-Luau files (or whole folders) to copy verbatim into the exe folder next to the built launcher. Unlike assets/, the contents are NOT packed into a .managed bundle; they sit on disk beside the game where third-party SDKs and OS loaders expect them. Use for:

  • Steamworks side files like steam_appid.txt.
  • Third-party DLLs that aren't FFI-loaded (e.g. openvr_api.dll, EOS / Discord SDK).
  • License / readme / changelog text the player should see.
  • Data folders read by external tools you ship.

Each entry is a path relative to the project root. Files go to Generated/<same path>; folders are copied recursively with structure preserved (so "localization/" becomes Generated/localization/...). Absolute paths and .. traversals are rejected with a warning.

For Rust FFI DLLs, prefer the dedicated bin/ folder (auto-detected, see FFI) over include — bin/ is what FFI.Load probes.

The implicit bin/ folder

Separately from include, the builder always copies a bin/ directory at the project root (and inside any package / DLC folder) recursively into Generated/bin/. This is the home for FFI Rust DLLs and any other native libraries the engine should pick up via FFI.Load. Nothing in build.toml needs to mention it — it's convention-over-configuration. 

my-game/
  bin/
    ruzit_ffi_audio_dsp.dll     -- auto-copied to Generated/bin/
    ruzit_ffi_pathfinder.dll
  Packages/
    rendering-utils/
      ManagedInfo.toml
      bin/
        renderkit.dll           -- also auto-copied (merged in)
  build.toml
  Main.luau
